Key Explanations for Commonly Missed Questions

Q4 — Ridge vs Lasso
Why does Lasso perform feature selection but Ridge does not?
✅ B — The L1 diamond constraint region has corners on coordinate axes; the OLS ellipsoid is likely to be tangent at a corner, giving exact zeros.
Ridge L2 constraint: {β: Σβᵢ² ≤ t} is a smooth sphere — the OLS loss ellipsoid can be tangent to this sphere at infinitely many non-axis points. Ridge shrinks all coefficients toward zero but rarely reaches exactly zero. Lasso L1 constraint: {β: Σ|βᵢ| ≤ t} has corners at axis intersections (e.g., β = (t,0,0,...,0)). When the OLS loss ellipsoid intersects the diamond, it is geometrically very likely to be tangent at a corner — setting one or more coefficients exactly to zero. This automatic feature selection is why Lasso is preferred when you expect sparsity.
Q10 — Q-value interpretation
What does Q*(s₁, ATTACK)=18.7 represent, and why is ATTACK only optimal in state s₁?
✅ B — Expected cumulative discounted reward from s₁ taking ATTACK and then acting optimally; optimality is state-dependent.
Q*(s,a) = E[Σ γᵏrₜ₊ₖ | s₀=s, a₀=a, π*]. The 18.7 is NOT a probability, NOT an immediate reward — it is the expectation over all future discounted rewards assuming optimal play after the first ATTACK action. In state s₁ (high ammo, terrain cover, enemy adjacent): ATTACK leads to kills (+5), objective capture (+10), discounted future wins. In state s₂ (exposed, low ammo): Q*(s₂,ATTACK) might be 4.1 while Q*(s₂,DEFEND)=12.3. The entire point of learning Q* is to capture this state-dependence: different tactical situations warrant different actions.
Q12 — PPO clipping
Compute L_CLIP for r_t=1.583, Â=+6.8, ε=0.2.
✅ A — r_t=1.583 > 1+ε=1.2, clipped; L_CLIP = 1.2×6.8 = 8.16
r_t = π_new/π_old = 0.19/0.12 = 1.583. Â=+6.8 > 0 (good action — want to increase probability). clip(1.583, 0.8, 1.2) = 1.2 (upper bound hit — policy increased too fast). Unclipped = 1.583×6.8 = 10.76. Clipped = 1.2×6.8 = 8.16. min(10.76, 8.16) = 8.16 (clipped wins — lower value is more conservative). PPO limits this good action's probability increase to 20% per update, even though advantage strongly suggests going further. This prevents overshooting into an unstable policy.

Q1 — Cross-Lecture Pipeline Design [12 Marks]
L1 L2 L4 L5
A CERT team monitors a military network with 2 million packets per day. The training data has: 1.9 million labelled normal packets, 80,000 labelled known-attack packets (4%), and approximately 20,000 unlabelled packets of unknown origin.

(a) Identify which packets should be used to train each of the following, and justify: (i) a supervised threat classifier, (ii) an Isolation Forest, (iii) an Autoencoder anomaly detector. [4 marks]
(b) Design a 3-tier deployment pipeline specifying: what each tier does, which algorithm runs at each tier, the latency requirement at each tier, and what information passes between tiers. [5 marks]
(c) The team discovers their labelled attack data only contains DoS and Probe attacks. A new R2L attack type appears in production. Which tier(s) of your pipeline will detect it, and which will miss it? Explain. [3 marks]
Show Full Solution

(a) Training data allocation:

$$ (i) SUPERVISED THREAT CLASSIFIER: Use: 1.9M normal + 80K labelled attacks (known classes only) Purpose: Identify KNOWN attack patterns (DoS, Probe) with high precision Rationale: Supervised learning requires labels for each class WARNING (L1): The 20K unlabelled packets must NOT be included without validation — they may contain novel attacks that would contaminate labels Handle imbalance: attack:normal = 4:96 → apply class weighting 24× for attack class, or SMOTE to generate synthetic attack samples (ii) ISOLATION FOREST: Use: ONLY the 1.9M normal packets (no attacks in training!) Purpose: Learn the distribution of NORMAL to isolate deviations Rationale: IF is semi-supervised anomaly detection — it learns the "normal manifold" and flags anything isolated from it Including attack data in IF training would make attacks LESS anomalous (IF would learn "attack patterns are also somewhat normal") The 20K unlabelled packets: EXCLUDE from training (may be attacks) (iii) AUTOENCODER ANOMALY DETECTOR: Use: ONLY the 1.9M normal packets (train only on normal!) Purpose: Learn to reconstruct normal traffic; high RE = anomaly Rationale: AE trained only on normal traffic learns normal patterns perfectly — attack packets produce high reconstruction error because the AE never learned to reconstruct attack feature patterns 20K unlabelled: DO NOT include — same contamination risk as IF $$

(b) 3-Tier Pipeline Design:

$$ TIER 1: ISOLATION FOREST (Real-Time Screening) Algorithm: Isolation Forest (B=100, ψ=256) Latency: ≤0.002ms per packet (handles 2M/day = 23 packets/second average) What it does: Screens ALL 2M daily packets for statistical anomalies Threshold: s* chosen for FPR=1.1% → flags ~22,000 packets/day as suspicious Output → Tier 2: flagged packet features + anomaly score s(x) Handles: NOVEL zero-day attacks (zero-day advantage!) Misses: Sophisticated attacks designed to blend with normal distribution TIER 2: COMBINED AUTOENCODER + SUPERVISED CLASSIFIER Algorithm: AE (reconstruction error) + RF classifier (ensemble decision) Latency: ≤0.04ms per packet × 22,000 packets = 0.88 seconds (fine!) What it does: Deep-scans Tier-1 flagged packets with two independent signals: AE RE: Is this statistically unlike normal traffic? (unsupervised) RF confidence: Does this match a known attack signature? (supervised) Decision rule: Flag if (RE > τ_AE) OR (RF class ≠ 'Normal' with P > 0.80) Output → Tier 3: confirmed anomalies with AE RE breakdown + RF class label Handles: Both known attacks (RF) and unknown anomalies (AE) TIER 3: ANALYST INVESTIGATION Latency: 1–10 minutes per alert What it does: Human CERT analyst reviews per-feature RE breakdown, checks against threat intelligence feeds, updates threat library Inputs: AE per-feature RE (SHAP-explained), RF class probabilities, packet metadata, historical context from similar packets Output: Confirmed/dismissed alert + threat library update + IOC (Indicators of Compromise) if new attack pattern confirmed $$

(c) Novel R2L attack — which tiers detect it:

$$ WILL DETECT: Tier 1 (IF) and Tier 2 (AE) Tier 1 (IF): Detects because R2L is statistically anomalous vs normal traffic R2L involves failed login attempts, unusual auth sequences → these create unusual values in src_bytes, failed_logins, num_shells features → short path length in IF trees → high anomaly score s(x) → flagged ✓ Tier 2 (AE): Detects because R2L features were never seen in training The AE trained on normal traffic cannot reconstruct R2L auth patterns → high reconstruction error on failed_logins, auth_protocol features ✓ WILL MISS (partially): Tier 2 Supervised RF Classifier RF was trained only on DoS + Probe attack classes R2L produces a novel feature pattern not in the RF training distribution RF will likely classify R2L as 'Normal' (nearest known class in RF decision space is normal traffic, since R2L has never been seen) HOWEVER: the AE in Tier 2 still catches it — so the COMBINED tier-2 system succeeds even though the RF component fails KEY INSIGHT: This is exactly why a HYBRID tier-2 (AE + RF) outperforms either alone: AE covers novel attacks that RF misses; RF precisely classifies known attacks that may have borderline AE reconstruction error. $$
Mark Scheme: (a) 4 marks (1 per method × 3 + unlabelled handling 1). (b) 5 marks (Tier 1: 1.5, Tier 2: 2, Tier 3: 1, information flow 0.5). (c) 3 marks (IF detects 1, AE detects 1, RF misses but combined succeeds 1).
Q2 — Algorithm Selection Justification [10 Marks]
L2 L4 L6 L8
For each of the following four defence AI problems, select the MOST appropriate algorithm from the course, justify in 2–3 sentences referencing specific course concepts, and name ONE key metric to validate success.

(a) You have 50,000 past radar tracks labelled by experienced analysts as: Fighter, Bomber, Helicopter, UAV, or Civilian. You want to classify new tracks in real-time (<10ms). [2.5 marks]
(b) You have 12,000 OPFOR patrol logs with NO analyst labels. You want to discover if there are distinct patrol patterns and identify any that look like reconnaissance/deception activity. [2.5 marks]
(c) A wargame simulation has 12 discrete actions per unit and a 30×30 hex grid. You want to train an advisory system that suggests the top-3 actions with estimated values. [2.5 marks]
(d) A naval task force of 5 platforms needs to coordinate interception of an adversary convoy, with limited communications bandwidth at sea. [2.5 marks]
Show Full Solution
$$ (a) RANDOM FOREST for radar track classification Algorithm: Random Forest (B=500 trees, max_depth=12) Justification: Labelled data → supervised classification (L2). RF is the course's best-performing classifier (97.5% on IADS), handles multi-class naturally via class-vote, is robust to noisy radar features, provides feature importance for explainability (important for ROE compliance), and can run inference in <1ms (well within 10ms budget). SVM is an alternative but requires careful kernel selection; DNN would need more data; XGBoost is also strong here. Key validation metric: Per-class Recall (especially for Fighter/UAV which may be rare and most operationally critical). Also: AUROC per class. (b) DBSCAN + k-MEANS COMBINATION for OPFOR patrol discovery Algorithm: Run k-Means first (fast first pass, elbow + silhouette for k), then DBSCAN (ε, MinPts from k-distance plot) as second method Justification: No labels → unsupervised clustering (L4). The question has TWO requirements: (1) discover distinct patrol patterns → k-Means is fast and gives clean archetype centroids with interpretable features; (2) identify deception/reconnaissance → DBSCAN's NOISE POINTS are the key: unusual patrol logs that don't fit any dense cluster are exactly the deception manoeuvres. k-Means alone would force these into clusters, hiding them. Use DBSCAN's noise to specifically flag 'unclassified/anomalous' patrols. Key validation metric: Silhouette score (>0.65 = strong structure) + expert label agreement on random sample (ARI with analyst review). (c) DQN (Dueling + Double) for wargame advisory system Algorithm: Dueling + Double DQN with experience replay Justification: Interactive environment + discrete actions → RL, specifically Q-Learning family (L6). Dueling DQN decomposes Q into V(s)+A(s,a), which is ideal for the advisory role: V(s) tells the commander "how good is this overall position?" and A(s,a) tells "which of the 12 actions is most beneficial?" Double DQN corrects overestimation bias for more reliable Q-value advisory numbers. Output: top-3 actions with Q-values = the exact advisory format needed. MAPPO would be overkill for a single-agent problem. Key validation metric: Win rate vs novice human player (target >80%) and Q-value correlation with actual game outcomes (Bellman error). (d) MAPPO with CTDE for naval multi-platform coordination Algorithm: MAPPO (Multi-Agent PPO) with Centralised Training Decentralised Execution Justification: Multiple agents + cooperative task → MARL (L8). CTDE is essential: during training, the centralised critic V(s) takes the full naval picture (all 5 platform positions, convoy tracks, patrol aircraft). At execution: each platform's actor π_i(a_i|o_i) runs on LOCAL observations only — no inter-ship communication needed at execution time. This is the KEY operational advantage for limited-bandwidth sea operations. QMIX is also valid but MAPPO handles the heterogeneous platforms (frigate vs helicopter vs submarine) better via agent-ID encoding, and supports continuous actions for helicopter navigation. Key validation metric: Mission success rate (convoy intercepted >80%) and friendly casualties per engagement (lower = better). Also: performance in communication-DENIED scenario to validate decentralised execution. $$
Mark Scheme: 2.5 marks per question: algorithm selection (0.5), justification referencing course concepts (1.5), key metric (0.5). Strong answers connect to specific numerical results from course case studies.
Q3 — Integrated Numerical Chain [12 Marks]
L2 L3 L6
An integrated air defence system (IADS) pipeline has three stages. Work through each calculation.

Stage 1 (L2 — Classification): A target produces features: speed=1,200 km/h, altitude=8,000m, radar cross-section=0.8m². The kNN classifier (k=5) compares it to the 5 nearest training neighbours: 2 Fighter (d=0.4, 0.6), 2 Bomber (d=0.8, 1.1), 1 UAV (d=0.9). Determine the predicted class. [2 marks]

Stage 2 (L3 — Sensor Fusion): Radar reports range z_R = 85.0 km (R_R = 1.0 km²). IR sensor reports z_IR = 87.5 km (R_IR = 6.25 km²). Kalman prediction: x̂_{k|k-1} = 84.0 km, P_{k|k-1} = 2.25 km². Using sequential Kalman updates (update with Radar first, then IR), compute the final fused estimate x̂_{k|k} and the updated uncertainty P_k|k after both updates. Use K = P/(P+R). [6 marks]

Stage 3 (L6 — Decision Support): The fused track is now at range 85.2 km, closing at 400 m/s (time to engagement boundary: 180 seconds). The wargame DQN agent has Q-values: Q(ENGAGE)=14.8, Q(TRACK)=11.2, Q(EVADE)=7.4, Q(ALERT_HQ)=13.1. The agent uses ε=0.05, |A|=4 actions. (a) What is the greedy action? (b) What is P(ALERT_HQ)? (c) What should a human operator consider before executing the DQN's recommended action? [4 marks]
Show Full Solution

Stage 1 — kNN Classification:

$$ kNN with k=5. Count votes from 5 nearest neighbours: Neighbour 1: Fighter (d=0.4) Neighbour 2: Fighter (d=0.6) Neighbour 3: Bomber (d=0.8) Neighbour 4: UAV (d=0.9) Neighbour 5: Bomber (d=1.1) Vote count: Fighter = 2, Bomber = 2, UAV = 1 TIE between Fighter and Bomber! Standard kNN tie-breaking: use NEAREST neighbour among tied classes Nearest Fighter: d=0.4 Nearest Bomber: d=0.8 Winner: FIGHTER (nearest among tied classes) Predicted class: FIGHTER Confidence: 2/5 = 40% (weak! — should flag for secondary review) $$

Stage 2 — Sequential Kalman Fusion:

$$ STEP 1: Radar Update (x̂_{k|k-1}=84.0, P=2.25, z_R=85.0, R_R=1.0) K_R = P/(P+R_R) = 2.25/(2.25+1.0) = 2.25/3.25 = 0.6923 x̂_after_radar = x̂_{k|k-1} + K_R(z_R − x̂_{k|k-1}) = 84.0 + 0.6923×(85.0−84.0) = 84.0 + 0.6923×1.0 = 84.0 + 0.692 = 84.692 km P_after_radar = (1−K_R)×P = (1−0.6923)×2.25 = 0.3077×2.25 = 0.692 km² STEP 2: IR Update (use result from Step 1 as new prior) New prior: x̂=84.692 km, P=0.692 km² IR measurement: z_IR=87.5 km, R_IR=6.25 km² K_IR = P_after_radar/(P_after_radar+R_IR) = 0.692/(0.692+6.25) = 0.692/6.942 = 0.09969 ≈ 0.0997 x̂_final = 84.692 + 0.0997×(87.5−84.692) = 84.692 + 0.0997×2.808 = 84.692 + 0.280 = 84.972 km P_final = (1−0.0997)×0.692 = 0.9003×0.692 = 0.623 km² FINAL FUSED ESTIMATE: Range: 84.97 km (vs Radar: 85.0 km, IR: 87.5 km) Uncertainty: P = 0.623 km² (σ = 0.79 km) INTERPRETATION: Radar (P=2.25) × correction by R_R=1.0 → P dropped to 0.692 IR (R_IR=6.25) adds very little new info (K_IR only 10%) → Final estimate heavily weighted toward radar (more precise sensor) → IR barely moves the estimate from 84.692 to 84.972 km $$

Stage 3 — DQN Decision Support:

(a) GREEDY ACTION: Q(ENGAGE)=14.8 ← HIGHEST → Greedy action = ENGAGE (b) P(ALERT_HQ) with ε=0.05, |A|=4: ALERT_HQ is NOT the greedy action (Q=13.1 < Q(ENGAGE)=14.8) P(ALERT_HQ) = ε/|A| = 0.05/4 = 0.0125 (1.25%) P(ENGAGE) = (1−ε) + ε/|A| = 0.95 + 0.0125 = 0.9625 (Note: at deployment, ε should be 0 — pure greedy. ε=0.05 only during training) (c) HUMAN OPERATOR CONSIDERATIONS before executing ENGAGE: ① ROE VERIFICATION: Q-value advisory is NOT a firing authority. The DQN was trained to maximise engagement success in simulation. Does the current ROE permit engagement at 84.97 km range? Is the target positively identified (Fighter class with only 40% kNN confidence — weak! The tied kNN result should trigger secondary ID)? ② PROPORTIONALITY: Is engagement proportionate? Fused range 84.97 km, closing at 400 m/s → 213 seconds to boundary. Time allows re-verification. If fused range uncertainty = ±0.79 km, is the target actually within engagement boundary? ③ IFF/DISTINCTION: kNN predicted Fighter (40% confidence — tied vote). Has IFF (Identification Friend or Foe) confirmed hostile intent? Speed 1,200 km/h and altitude 8,000m match fighter profile but also match some commercial fast jets. Require additional confirmation. ④ Q-VALUE GAP: ENGAGE(14.8) vs ALERT_HQ(13.1) — gap of only 1.7 units. This is a relatively SMALL advantage for ENGAGE over ALERT_HQ. The model is not overwhelmingly confident. ALERT_HQ may be the appropriate first action while additional classification is performed. RECOMMENDED HUMAN DECISION: ALERT_HQ first (Q=13.1), get additional identification, THEN ENGAGE if hostile confirmed (Q=14.8 still highest). This is exactly the Level 2 Human-on-the-Loop advisory mode in action.
Mark Scheme: Stage 1: 2 marks (tie identified 1, fighter winner 1). Stage 2: 6 marks (K_R 1, x̂ after radar 1, P after radar 1, K_IR 1, x̂_final 1, P_final 1). Stage 3: 4 marks (greedy action 0.5, P(ALERT_HQ) 0.5, human considerations 3 — at least 3 distinct considerations required for full marks).
Q4 — Ethical AI & System Design [6 Marks]
L1 L5 L8
A Ministry of Defence committee is evaluating an autonomous system that uses MAPPO (trained in simulation) to recommend engagement actions against suspected hostile vehicles in an urban area. The system's developer claims 84% success rate in simulation and requests deployment at Level 3 autonomy (human out of the loop) to "match adversary AI speed."

(a) Identify THREE specific technical or ethical objections to this deployment proposal, citing specific course concepts and data from the course case studies. [4 marks]
(b) Propose a modified deployment architecture at Level 2 (human on the loop) that addresses the developer's concern about adversary AI speed while maintaining meaningful human control. [2 marks]
Show Full Solution

(a) Three objections to Level 3 autonomous deployment:

$$ OBJECTION 1: SIM-TO-REAL GAP MAKES THE 84% CLAIM MISLEADING Course data: MAPPO combined arms achieved 82.4% in simulation but estimated ~65% in real operations (16-20pp sim-to-real gap is typical — see L7: PPO drone 94%→78%, L8 discussion). Urban environments add additional complexity (civilian presence, non-combatant vehicles, visual similarity of civilian/military vehicles) not fully modelled in combat simulations. Claiming 84% simulation performance as evidence for autonomous lethal action in urban areas is methodologically flawed. An independent operational trial (not simulation) is required before any deployment — never mind Level 3 autonomous. OBJECTION 2: IHL PROPORTIONALITY CANNOT BE AUTOMATED (L8 Ethics) IHL Article 51(5)(b) requires assessment of whether expected civilian harm is excessive relative to anticipated military advantage. This is a contextual legal judgment requiring: - Dynamic identification of protected persons (civilians, surrendering combatants, medical personnel) in real-time urban chaos - Assessment of strategic military advantage in THIS political context - Understanding of collateral damage to civilian infrastructure MAPPO optimises a reward function (L8: r_OPFOR_killed = +10, r_own_lost = -15) — this is NOT proportionality assessment. The reward function CANNOT encode IHL proportionality; this objection is legally and technically fundamental. OBJECTION 3: ADVERSARIAL ADAPTATION + NO REAL-TIME LEARNING (L8) The committee is told "adversary AI speed" requires Level 3. However: MAPPO's fixed trained policy can be REVERSE-ENGINEERED by adversaries who observe it in operations (L8: same warning for the combined arms case study). Level 3 autonomous MAPPO repeating the same learned patterns is actually MORE vulnerable to adversarial exploitation than a human commander who adapts in real-time. The "adversary AI speed" argument is a red herring: human + AI at Level 2 can make decisions in 1-2 seconds — fast enough to counter most adversary tempo while maintaining IHL compliance. $$

(b) Level 2 modified deployment architecture:

$$ MODIFIED ARCHITECTURE: "1-Second Confirmation Loop" Speed concern: If adversary AI acts in 0.5 seconds, human review of 5 minutes is tactically unacceptable. Solution: TIERED DECISION WINDOWS. TIER A (automated, Level 1): Pure defensive actions MAPPO can automatically activate defensive countermeasures: - Smoke/IR decoys (passive defence, no civilian harm risk) - Evasive manoeuvring of own platforms - Passive electronic countermeasures These require no human confirmation — fully automated is IHL-compliant for defensive measures. TIER B (1-second confirmation, Level 2): Non-lethal active responses MAPPO recommends: top-3 actions with Q-values + confidence % Operator sees: visual overlay on threat track + Q-values Human action: single-button CONFIRM or OVERRIDE within 1-2 seconds This matches adversary AI tempo while preserving meaningful human control. Key: the confirmation is GENUINE (operator has been trained to evaluate key indicators in 1 second) not rubber-stamping. TIER C (10-30 second deliberate review, Level 2): Lethal engagement MAPPO recommends engage action with full justification: - Per-feature explanation (SHAP on threat classification) - Kalman-fused range/velocity with uncertainty - IFF status + confidence - ROE compliance check (automated rule engine) Human operator (and commander if possible) confirms lethal action. 30 seconds for lethal action in most urban scenarios is operationally acceptable and maintains the legally required meaningful human control. $$
Mark Scheme: (a) 4 marks — 3 objections, at least 2 must cite specific course data/concepts. Accept any 3 of: sim-to-real gap, IHL proportionality, adversarial adaptation, data distribution (urban≠simulation), scenario generality, emergent behaviour unpredictability. (b) 2 marks: tiered architecture with speed vs control trade-off addressed (1), specific mechanism for genuine rather than rubber-stamp human confirmation (1).
