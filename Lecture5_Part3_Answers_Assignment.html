B

Selected Explanations

Q3
Why do anomalies have shorter path lengths in Isolation Forest?
✅ B — Dense normal points need many splits; sparse anomalies are isolated in 1–2 cuts
The geometric insight: a DoS packet with src_bytes=1.2 (vs normal 3,000–8,000) sits far from the dense normal cluster. Any random split on the src_bytes feature immediately puts it alone on one side. Normal packets have thousands of similar neighbours; a random split through the cluster divides neighbours but leaves the target still surrounded by many similar points — requiring many more splits. This density difference is the core mechanism, not any preference for "extreme values."
Q5
Why does ν=0.001 (very tight OCSVM boundary) cause poor anomaly detection?
✅ B — Near-zero training violations forces ultra-tight boundary; normal traffic variation exceeds it → high FPR
OCSVM with ν=0.001 allows only 0.1% of 482K normal training packets to lie outside the boundary — just 482 packets. Real network traffic has natural variation (backup jobs, large file transfers, bursts during patch cycles). These legitimate extreme-but-normal packets cannot be included inside the boundary, forcing it so tight that ordinary traffic exceeds it during testing. ν should approximate the expected contamination rate — for Case A where we expect ~3.6% anomalies, ν≈0.03–0.05 is sensible.
Q14
Daily inference times for IF and AE on 10M packets/day
✅ A — IF: 20 seconds/day; AE: 400 seconds/day; both feasible; AE worth it for 4.4% TPR gain
IF: 10M × 0.000002s = 20s/day (trivially real-time). AE: 10M × 0.00004s = 400s ≈ 6.7 min/day (comfortably feasible). The calculation is straightforward: both methods are fast enough for 10M/day screening. The 3-tier architecture makes this moot: IF screens all 10M packets in 20s; only flagged packets (say 1.1% = 110K) go to the AE → AE processes 110K × 0.04ms = 4.4 seconds. Total compute: 24.4 seconds/day for the full 3-tier pipeline on 10M packets.
Q15
Why Autoencoder detects zero-day APT while supervised RF fails
✅ B — RF learned discriminant between known attack classes; novel APT falls into 'normal' side of boundary
This is the fundamental epistemological difference: supervised methods learn "what attacks look like" (closed-world assumption). Novel attacks outside the training class distribution get classified as the nearest known class or as "normal." Anomaly detection learns "what normal looks like" (open-world assumption) — anything sufficiently different is flagged regardless of whether it matches a known attack signature. This is why real-world CERT deployments use BOTH: supervised IDS for known attack pattern matching + anomaly detection for zero-day coverage.

Q1 — Isolation Forest Path Length [8 Marks]
An Isolation Forest uses B=1 tree (for manual computation). The sub-sample is ψ=8 points. Five points are in a dense cluster near the origin: N1=(0.1,0.2), N2=(0.3,0.1), N3=(0.2,0.3), N4=(0.1,0.1), N5=(0.2,0.2). Three outliers: O1=(8.0,0.1), O2=(0.1,9.0), O3=(7.5,8.5).

(a) The first random split chosen is: feature x₁, value q=4.0. Which points go left (x₁ < 4) and right (x₁ ≥ 4)? [2 marks]
(b) The right branch now contains 3 points {O1, O3, O2 if applicable}. The next split is: feature x₂, value q=5.0. How does this further partition the right branch? [2 marks]
(c) After the x₂ split, O1=(8.0,0.1) is isolated (alone in its partition). What is h(O1) = path length at this point? [1 mark]
(d) In the left branch containing {N1–N5, O2}, a split on x₂ at q=5.0 separates O2. O2 is now isolated at depth 2. What is h(O2)? [1 mark]
(e) The 5 normal points {N1–N5} remain together after both splits. Using the normalisation c(ψ)=2H(ψ−1)−2(ψ−1)/ψ ≈ 3.46 for ψ=8, and assuming the normal points require average 5.2 more splits to isolate (total E[h]=7.2 from root), compute the anomaly scores s(O1) and s(N1) using $s(x,\psi)=2^{-E[h(x)]/c(\psi)}$. [2 marks]
Show Answer

(a) First split: x₁ < 4.0 (left) vs x₁ ≥ 4.0 (right):

Left branch (x₁ < 4.0): N1(0.1), N2(0.3), N3(0.2), N4(0.1), N5(0.2), O2(0.1) → 6 points Right branch (x₁ ≥ 4.0): O1(8.0), O3(7.5) → 2 points (O2 has x₁=0.1 < 4.0 → goes LEFT)

(b) Second split on right branch: x₂ < 5.0 vs x₂ ≥ 5.0:

Right branch had: O1=(8.0, 0.1) and O3=(7.5, 8.5) Split x₂ at 5.0: Left sub-branch (x₂ < 5.0): O1=(8.0, 0.1) → 1 point Right sub-branch (x₂ ≥ 5.0): O3=(7.5, 8.5) → 1 point Both O1 and O3 are now ISOLATED (each alone in their partition)

(c) Path length h(O1):

$$ O1 path: Root → x₁ split (depth 1) → x₂ split (depth 2) → ISOLATED h(O1) = 2 (isolated at depth 2, after 2 splits from root) $$

(d) Path length h(O2):

O2=(0.1, 9.0) went LEFT at first split (x₁=0.1 < 4.0) Left branch: {N1,N2,N3,N4,N5,O2} — 6 points Second split on x₂ at 5.0: x₂ < 5.0: {N1(0.2),N2(0.1),N3(0.3),N4(0.1),N5(0.2)} → 5 points x₂ ≥ 5.0: {O2(0.1,9.0)} → ISOLATED at depth 2 h(O2) = 2 (isolated at depth 2)

(e) Anomaly scores:

c(ψ=8) ≈ 3.46 (given) For O1: E[h(O1)] = 2 (isolated in 2 splits) s(O1) = 2^{−2/3.46} = 2^{−0.578} = 1/2^{0.578} 2^{0.578}: 2^{0.5}=1.414, 2^{0.578}≈1.494 s(O1) = 1/1.494 = 0.669 → ANOMALY (s > 0.6 threshold) For N1: E[h(N1)] = 7.2 (given — hard to isolate in dense cluster) s(N1) = 2^{−7.2/3.46} = 2^{−2.081} = 1/2^{2.081} 2^{2.081}: 2^2=4.0, 2^{0.081}≈1.058 → 2^{2.081}≈4.231 s(N1) = 1/4.231 = 0.236 → NORMAL (s < 0.5 threshold) INTERPRETATION: O1 score 0.669 >> N1 score 0.236 → Clear separation between anomaly and normal points!
Mark Scheme: (a) 2 marks (1 per branch). (b) 2 marks. (c) 1 mark. (d) 1 mark. (e) 2 marks (1 per score computation).
Q2 — Autoencoder Threshold & FPR/TPR Analysis [10 Marks]
An Autoencoder is trained on 100,000 normal network packets. Validation results:
Normal packets (N=10,000): RE follows N(0.030, 0.015²) approximately.
Attack packets (N=500): RE follows N(0.280, 0.090²) approximately.

(a) At threshold τ=0.060, compute the approximate FPR on normal packets using Z-score (assume normal distribution). [3 marks]
(b) Compute the approximate TPR (attack detection rate) at the same threshold τ=0.060. [3 marks]
(c) If the operational requirement is FPR ≤ 1%, find the threshold τ_1% that achieves exactly 1% FPR. [2 marks]
(d) At τ_1%, what is the resulting TPR? Is this operationally acceptable for a national CERT? [2 marks]
Show Answer

(a) FPR at τ=0.060 (Normal RE ~ N(0.030, 0.015²)):

$$ FPR = P(RE_normal > τ) = P(Z > (τ − μ_normal)/σ_normal) = P(Z > (0.060 − 0.030)/0.015) = P(Z > 0.030/0.015) = P(Z > 2.0) From standard normal table: P(Z > 2.0) = 1 − Φ(2.0) = 1 − 0.9772 = 0.0228 FPR ≈ 2.28% at τ=0.060 In absolute numbers: 10,000 × 0.0228 = 228 normal packets falsely flagged $$

(b) TPR at τ=0.060 (Attack RE ~ N(0.280, 0.090²)):

TPR = P(RE_attack > τ) = P(Z > (τ − μ_attack)/σ_attack) = P(Z > (0.060 − 0.280)/0.090) = P(Z > −0.220/0.090) = P(Z > −2.444) = Φ(2.444) [by symmetry: P(Z > -a) = P(Z < a) = Φ(a)] Φ(2.44) ≈ 0.9927 Φ(2.45) ≈ 0.9929 Interpolate: Φ(2.444) ≈ 0.9928 TPR ≈ 99.28% at τ=0.060 In absolute numbers: 500 × 0.9928 = 497 attack packets detected (3 missed)

(c) Threshold τ for FPR = 1%:

$$ FPR = 1% = P(RE_normal > τ) = P(Z > (τ − 0.030)/0.015) = 0.01 P(Z > z*) = 0.01 → z* = 2.326 (from standard normal table: Φ(2.326) = 0.99) τ_1% = μ_normal + z* × σ_normal = 0.030 + 2.326 × 0.015 = 0.030 + 0.034886 = 0.0649 ≈ 0.065 $$

(d) TPR at τ_1% = 0.065:

$$ TPR = P(RE_attack > 0.065) = P(Z > (0.065 − 0.280)/0.090) = P(Z > −0.215/0.090) = P(Z > −2.389) = Φ(2.389) Φ(2.38) ≈ 0.9913, Φ(2.39) ≈ 0.9916 Φ(2.389) ≈ 0.9916 TPR ≈ 99.16% at τ_1% = 0.065 OPERATIONAL ACCEPTABILITY: FPR = 1.0% → on 10M packets/day → 100,000 false alerts/day This is operationally PROBLEMATIC without tier-2 filtering. With 3-tier architecture: AE deep-scan reduces 100K false alerts significantly → ACCEPTABLE. TPR = 99.16%: excellent for a CERT — missing only 0.84% of attacks (84 missed per 10,000 attacks) is acceptable if combined with other defensive layers. $$
Key insight: Moving τ from 0.060 (FPR=2.28%) to 0.065 (FPR=1%) barely affects TPR (99.28% → 99.16%) because the attack RE distribution is so far above the normal RE distribution. This "easy" separation is why autoencoders work well when the normal/anomalous distributions are well-separated. Mark: (a) 3, (b) 3, (c) 2, (d) 2.
Q3 — OCSVM ν Parameter Design [10 Marks]
A CERT analyst is designing an OCSVM for network anomaly detection. The training set has 50,000 normal packets (cleaned, no attacks known at training time). The analyst estimates the production traffic will contain approximately 2% attack traffic.

(a) What value of ν should the analyst start with and why? [2 marks]
(b) After training OCSVM with ν=0.02, the model flags 1,400 of the 50,000 training packets as outside the boundary (margin violations). Is this expected? Explain using the ν interpretation. [3 marks]
(c) A colleague suggests ν=0.20 "to be safe and catch more anomalies." Explain why this is incorrect reasoning and what the actual consequence would be. [3 marks]
(d) The final deployed model with ν=0.02, γ=0.10 achieves FPR=1.8% and TPR=88.2% on the test set (which has 2% attacks). The analyst's manager requests "both FPR and TPR should be improved simultaneously." Explain why this is mathematically impossible with a fixed model, and what the actual options are. [2 marks]
Show Answer

(a) Starting ν value and justification:

$$ Start with ν = 0.02 (matching the estimated 2% attack traffic rate) Justification: ν is the upper bound on the fraction of training points that can be outside the boundary. If 2% of production traffic is attacks, and assuming some attack contamination leaked into training despite cleaning, setting ν≈contamination_fraction is the principled starting point. Also: ν is the lower bound on support vectors. With ν=0.02 and N=50,000: Min support vectors = 0.02 × 50,000 = 1,000 This gives a rich enough boundary representation for 50K training points. $$

(b) Is 1,400 violations expected?

$$ ν = 0.02 → upper bound on fraction of training violations Maximum violations allowed = ν × N = 0.02 × 50,000 = 1,000 1,400 violations > 1,000 (the ν bound) This seems to violate the ν constraint — BUT: The ν parameter is an asymptotic bound, not a strict constraint in all finite cases. The actual fraction = 1,400/50,000 = 2.8%, slightly above ν=2%. In practice, this means the RBF kernel bandwidth γ=0.10 may be too large (too flexible a boundary that still has violations), or ν needs slight adjustment. The analyst should: 1. Check if increasing γ slightly (e.g., 0.08) tightens the boundary 2. Or accept 2.8% ≈ 2% as close enough (within noise of finite-sample effects) Alternatively: if training data was 100% clean (no attack contamination), the 1,400 violations are legitimate normal-traffic outliers — edge cases of normal behaviour that the model correctly treats as uncertain. $$

(c) Why ν=0.20 is wrong:

$$ ν=0.20 → allows 20% of training data outside boundary = 10,000 packets The boundary becomes VERY LOOSE — it only needs to enclose 80% of normal traffic. CONSEQUENCE: Many genuinely normal packets lie outside this loose boundary. At test time, normal packets that were outside the training boundary → flagged as anomalies → FPR explodes (far above 2%). The colleague's reasoning "more ν = catch more anomalies" is BACKWARDS: Higher ν → LOOSER boundary → more normal data outside → higher FPR Lower ν → TIGHTER boundary → less normal data outside → lower FPR → BUT may miss subtle anomalies ν controls the boundary TIGHTNESS, not the "anomaly sensitivity" directly. The correct way to catch more anomalies is to adjust the DECISION THRESHOLD or use a more powerful model (Autoencoder), not to increase ν. $$

(d) Why FPR and TPR cannot both improve simultaneously:

$$ For a FIXED trained model, FPR and TPR are linked by the ROC curve. Decreasing threshold → flags more packets → TPR ↑ but FPR ↑ too Increasing threshold → flags fewer packets → FPR ↓ but TPR ↓ too Moving along the ROC curve: TPR and FPR are POSITIVELY CORRELATED for any fixed model — you cannot increase one while decreasing the other. The ONLY ways to improve BOTH simultaneously: 1. Train a BETTER MODEL (e.g., Autoencoder instead of OCSVM) that achieves a higher AUROC — a better model has its entire ROC curve shifted toward the top-left corner (higher TPR at same FPR) 2. Add more/better FEATURES that better distinguish normal from attack 3. Use an ENSEMBLE of OCSVM + Isolation Forest + threshold calibration to achieve a better combined ROC point than either alone $$
The ROC curve insight is fundamental: for any fixed model, the operating point moves along the ROC curve as threshold changes. Improving both FPR AND TPR requires improving the model itself (higher AUROC), not adjusting the threshold. Mark: (a) 2, (b) 3, (c) 3, (d) 2.
Q4 — Insider Threat Multi-Modal Design [12 Marks]
A defence establishment wants to deploy an insider threat detection system for 1,000 employees. The CISO specifies: "We need to detect compromised credentials within 24 hours with ≥ 85% detection rate and ≤ 0.5% false positive rate per month."

(a) The organisation has three candidate approaches: (i) Rule-based alerts only (e.g., after-hours login), (ii) LSTM Autoencoder on temporal sequence of events, (iii) Multi-modal anomaly detection combining temporal + content + volume features. Rank these by expected performance on the CISO's requirements and justify. [4 marks]
(b) Design the feature vector for the multi-modal approach. List 10 features across three modalities (temporal, content-access, communication), specifying for each: the modality, feature type (count/rate/flag/categorical), and expected value range for a normal user. [4 marks]
(c) The system flags User X for investigation. The LSTM AE reports RE=0.412 (threshold τ=0.090). The per-feature reconstruction errors are: Login_hour_deviation: 0.248, Files_accessed_fin: 0.089, Files_accessed_hr: 0.062, Ext_email_count: 0.013. Write a one-paragraph analyst brief explaining what behaviour drove the anomaly, suitable for submission to a security officer who is not an ML expert. [4 marks]
Show Answer

(a) Ranking and justification:

Rank 1: Multi-modal (best). Combines temporal (WHEN), content (WHAT), volume (HOW MUCH), and communication (WHO) dimensions. A sophisticated attacker who operates during business hours evades temporal-only detection, but cross-domain data access (finance + HR + engineering in one session) and unusual external email count still flag them. Multi-modal covers the detection gaps of each single-modality approach. Expected: ≥85% TPR, ≤0.5% FPR/month achievable with careful feature engineering and threshold calibration.

Rank 2: LSTM Autoencoder (temporal). Captures temporal sequence patterns automatically, detecting deviations from established user timing baselines. Achieves 86.7% TPR in Case B. However misses the 2 accounts who operated during normal hours. FPR depends heavily on how much legitimate after-hours work occurs in the organisation. For 1,000 users, 0.5% FPR/month = ≤5 false alerts/month — achievable with per-user personalised thresholds but challenging for users with irregular work patterns.

Rank 3: Rule-based (weakest). Simple rules (after-hours login → alert) have very high FPR in any real organisation (shift workers, overseas time zones, legitimate overtime) and very low TPR on sophisticated attackers who operate during business hours. Cannot be tuned to the CISO's 0.5% FPR requirement without making the rules so permissive they become useless.

(b) Multi-modal feature vector (10 features):

TEMPORAL MODALITY (4 features): F1: Login_hour [count/float] Normal: 8.0–18.0 hrs F2: Login_hour_deviation [float] Normal: < 2.0 hrs from personal μ F3: Weekend_login_flag [binary flag] Normal: 0 (most office workers) F4: Session_duration_minutes [count] Normal: 30–480 min/session CONTENT-ACCESS MODALITY (4 features): F5: Files_accessed_financial [count/day] Normal: 0–5 for non-finance staff F6: Files_accessed_HR [count/day] Normal: 0–2 for non-HR staff F7: Files_accessed_classified [count/day] Normal: varies by clearance level F8: Unique_folder_paths [count/day] Normal: 3–15 (routine work areas) COMMUNICATION MODALITY (2 features): F9: External_email_recipients [count/day] Normal: 1–8 unique external addresses F10: USB_data_transfer_MB [float/day] Normal: 0 MB (most users)

(c) Analyst brief for User X:

$$ SECURITY ALERT — USER X — ANOMALY SCORE: HIGH (RE=0.412, threshold=0.090) Summary for Security Officer: Our behavioural AI system has flagged User X for urgent investigation based on an unusual combination of activities that deviate significantly from their established work patterns. The most significant driver of this alert is a substantial LOGIN TIME DEVIATION (anomaly contribution score: 0.248 out of 0.412 total) — User X's account was accessed at an unusual hour well outside their typical working pattern. This alone is concerning. However, the alert is reinforced by UNUSUAL FILE ACCESS patterns: User X accessed significantly more FINANCIAL documents (score: 0.089) and HR records (score: 0.062) than is normal for their role. This cross-departmental data access is particularly suspicious when combined with the off-pattern login time. The combination of: (a) login outside normal hours, (b) accessing financial files beyond typical volume, and (c) accessing HR records atypical for their role, collectively indicates potential credential compromise or malicious insider activity. RECOMMENDED ACTION: Verify with User X's supervisor whether these activities were pre-authorised. If no authorisation, escalate to incident response. No unusual external email activity was detected (score: 0.013 — within normal range). $$
The analyst brief translates ML output (reconstruction error per feature) into actionable security intelligence: WHAT deviations occurred, HOW significant each was, and WHAT actions to take. The brief correctly identifies the dominant features, provides context (is this authorised?), and appropriately notes what WAS normal (no email anomaly). This is the bridge between ML anomaly detection and human decision-making. Mark: (a) 4, (b) 4, (c) 4.
