Selected Explanations

Q4
Why doesn't Q-Learning with constant α converge exactly to Q*=12.78?
✅ B — Constant α tracks a running average over stochastic TD targets; Robbins-Monro schedule needed for exact convergence
With constant α, the update Q ← (1−α)Q + α·target is a weighted average of all past TD targets. Since targets r + γ max Q(s',a') vary due to environment stochasticity and ε-greedy exploration, the converged Q equals E[target]≈11.8, not the true max-trajectory Q*=12.78. To achieve exact convergence to Q*, use α_t(s,a)=1/N_t(s,a) where N_t counts visits — this satisfies Σ α_t = ∞, Σ α_t² < ∞.
Q8
Why does standard DQN systematically overestimate Q-values?
✅ B — max operator selects the noisiest estimate; E[max noisy] > max E[noisy] by Jensen's inequality
For K actions with estimates Q̂ᵢ = Qᵢ* + εᵢ (noise), max_i Q̂ᵢ = max_i(Qᵢ* + εᵢ). Even if E[εᵢ]=0, E[max εᵢ] > 0 (maximum of zero-mean random variables has positive expectation — the maximum is pulled upward). Double DQN: argmax from θ selects a* (possibly due to high noise in θ), then Q(s',a*;θ⁻) evaluates it with independent θ⁻ noise. Since θ⁻ doesn't necessarily overestimate a*, the bias is reduced from O(K) to near-zero.
Q11
Why does potential-based shaping preserve the optimal policy?
✅ B — Telescoping sum over any trajectory = γΦ(s_T) − Φ(s_0) — independent of intermediate actions
Proof sketch: cumulative shaped reward = Σ γ^t[R(s_t,a_t) + F(s_t,s_{t+1})] = Σ γ^t R(s_t,a_t) + Σ γ^t[γΦ(s_{t+1})−Φ(s_t)]. The second sum telescopes to γ^T Φ(s_T) − Φ(s_0) — a constant added to every trajectory with the same start and terminal states. Adding a constant to all trajectories does not change their relative ranking → same optimal policy. Non-potential-based shaping (e.g., naive +2 for proximity) does NOT have this telescoping property and CAN change π*.

Q1 — Bellman Equation & Q-Value Derivation [10 Marks]
A simplified 3-state wargame MDP has deterministic transitions (P=1) and γ=0.9:

States: S₁ (start), S₂ (adjacent to objective), S₃ (objective captured = terminal)
Actions from S₁: {MOVE → S₂ (r=0), DEFEND → S₁ (r=+1)}
Actions from S₂: {ATTACK → S₃ (r=+10), RETREAT → S₁ (r=−2)}
State S₃: terminal (V*(S₃) = 0 by convention)

(a) Write the Bellman optimality equation for V*(S₂). Compute V*(S₂). [3 marks]
(b) Write the Bellman optimality equation for V*(S₁). Compute V*(S₁). [3 marks]
(c) Compute Q*(S₁, MOVE) and Q*(S₁, DEFEND). What is π*(S₁)? [4 marks]
Show Answer

(a) V*(S₂) — Bellman optimality equation:

V*(S₂) = max_a [R(S₂, a, s') + γ V*(s')] Actions from S₂: ATTACK → S₃: r=+10, V*(S₃)=0 Q(S₂, ATTACK) = 10 + 0.9×0 = 10.0 RETREAT → S₁: r=−2, V*(S₁) = unknown for now Q(S₂, RETREAT) = −2 + 0.9×V*(S₁) Since ATTACK gives +10 and RETREAT gives −2+0.9V*(S₁): For RETREAT to be optimal: −2 + 0.9×V*(S₁) > 10 → V*(S₁) > 13.3 — this would require V*(S₁) > V*(S₂) But V*(S₁) depends on V*(S₂). Let's check: ATTACK clearly gives at least +10 regardless. RETREAT back to S₁ gives ≤ +9 even if V*(S₁) were very large. Since ATTACK gives +10, V*(S₂) = max(10.0, −2 + 0.9×V*(S₁)) We will first compute V*(S₁) assuming ATTACK optimal at S₂: If V*(S₂) = 10: V*(S₁) = max(0+0.9×10, 1+0.9×V*(S₁)) MOVE: 9.0 DEFEND: 1 + 0.9×V*(S₁) Assuming MOVE optimal: V*(S₁) = 9.0 Check RETREAT: −2 + 0.9×9.0 = −2 + 8.1 = 6.1 < 10 ✓ ATTACK is optimal V*(S₂) = 10.0

(b) V*(S₁) — Bellman optimality equation:

V*(S₁) = max_a [R(S₁, a, s') + γ V*(s')] Actions from S₁: MOVE → S₂: r=0, V*(S₂) = 10.0 Q(S₁, MOVE) = 0 + 0.9×10.0 = 9.0 DEFEND → S₁: r=+1, V*(S₁) = ? (self-loop!) Q(S₁, DEFEND) = 1 + 0.9×V*(S₁) For DEFEND to be optimal: 1 + 0.9×V*(S₁) > 9.0 → 0.9×V*(S₁) > 8.0 → V*(S₁) > 8.89 Suppose V*(S₁) = x. If MOVE optimal: x = 9.0 Check DEFEND: 1 + 0.9×9.0 = 1 + 8.1 = 9.1 > 9.0 ← DEFEND WINS! If DEFEND optimal (self-loop): x = 1 + 0.9x → 0.1x = 1 → x = 10.0 Check MOVE: 0 + 0.9×10.0 = 9.0 < 10.0 ✓ DEFEND is indeed optimal! V*(S₁) = 10.0 (agent stays at S₁ defending indefinitely, earning +1 each turn!)

(c) Q*(S₁, MOVE) and Q*(S₁, DEFEND), optimal policy:

$$ With V*(S₁)=10.0, V*(S₂)=10.0, V*(S₃)=0: Q*(S₁, MOVE) = R(S₁,MOVE,S₂) + γ V*(S₂) = 0 + 0.9 × 10.0 = 9.0 Q*(S₁, DEFEND) = R(S₁,DEFEND,S₁) + γ V*(S₁) = 1 + 0.9 × 10.0 = 10.0 π*(S₁) = argmax_a Q*(S₁,a) = DEFEND (Q=10.0 > 9.0) INSIGHT: The optimal policy is to DEFEND INDEFINITELY at S₁! Reason: γ=0.9 discounts future rewards. Capturing the objective at turn t gives: 0.9^t × 10 (one-time reward). Defending each turn gives: 1 + 0.9 + 0.81 + ... = 1/(1−0.9) = 10. The infinite stream of +1 defensive rewards equals the discounted value of capturing the objective — and defending never risks losses! OPERATIONAL MORAL: Reward design matters enormously. If the mission requires capturing the objective, the MDP designer must make +100 (capture) >> 1/(1-γ) (defend reward stream). With γ=0.9 and +10 capture: defend dominates. With +100 capture: Q(MOVE) = 90 >> Q(DEFEND) = 10 → capture becomes optimal. $$
Mark Scheme: (a) 3 marks (equation 1, Q-values 1, V*=10 1). (b) 3 marks (DEFEND self-loop setup 1, solving for x 1, V*=10 1). (c) 4 marks (Q*(MOVE)=9 1, Q*(DEFEND)=10 1, π*=DEFEND 1, reward design insight 1).
Q2 — Q-Learning Update Walk-Through [10 Marks]
A Q-Learning agent plays the 3-state wargame from Q1. Initialise all Q-values to 0. α=0.5, γ=0.9, ε=0.2 (ε-greedy).

Episode 1 trajectory: S₁ →[MOVE]→ S₂ →[ATTACK]→ S₃ (terminal). Rewards: r=0 (S₁→S₂), r=+10 (S₂→S₃).

(a) Apply the Q-Learning update for the transition (S₂, ATTACK, r=10, S₃). Compute Q(S₂, ATTACK) after this update. [3 marks]
(b) Apply the Q-Learning update for the transition (S₁, MOVE, r=0, S₂). Use the Q-value from (a). Compute Q(S₁, MOVE) after this update. [3 marks]
(c) Episode 2: The agent is at S₁. ε=0.2, |A|=2 actions {MOVE, DEFEND}. Q(S₁,MOVE)=from (b), Q(S₁,DEFEND)=0. What is P(selecting MOVE)? The agent selects DEFEND (exploration). Reward r=+1, next state S₁ (self-loop). Apply the Q-Learning update for (S₁, DEFEND, r=1, S₁). [4 marks]
Show Answer

(a) Update for (S₂, ATTACK, r=10, S₃):

$$ Q-Learning update: $Q(s,a)\leftarrow Q(s,a)+\alpha\!\left[r+\gamma\max_{a^{\prime}}Q(s^{\prime},a^{\prime})-Q(s,a)\right]$ Transition: s=S₂, a=ATTACK, r=10, s'=S₃ (terminal) At terminal state S₃: max_{a'} Q(S₃, a') = 0 (no actions in terminal state) TD Target = r + γ × 0 = 10 + 0.9×0 = 10.0 TD Error = 10.0 − Q(S₂,ATTACK) = 10.0 − 0 = 10.0 Q(S₂, ATTACK) ← 0 + 0.5 × [10.0 − 0] = 0 + 5.0 = 5.0 After episode 1, step 1: Q(S₂, ATTACK) = 5.0 $$

(b) Update for (S₁, MOVE, r=0, S₂):

$$ Note: Q-Learning updates are typically done FORWARD in time (process transitions as they occur), but the update uses Q(s') values AT THE TIME of the update. In episode 1, transition (S₁,MOVE,r=0,S₂) occurred BEFORE (S₂,ATTACK). Q-Learning with replay would update in order: If updating forward (online, S₁ transition first): At time of S₁→S₂ transition: Q(S₂,ATTACK) was still 0! TD Target = 0 + 0.9 × max(Q(S₂,ATTACK)=0, Q(S₂,RETREAT)=0) = 0 Q(S₁,MOVE) ← 0 + 0.5×[0−0] = 0 If updating backward (or using updated Q(S₂)): Using Q(S₂,ATTACK)=5.0 computed in (a): TD Target = 0 + 0.9 × max(5.0, 0) = 0.9×5.0 = 4.5 TD Error = 4.5 − 0 = 4.5 Q(S₁,MOVE) ← 0 + 0.5 × 4.5 = 2.25 [Standard Q-Learning processes online: use Q(s') at time of update. For exam purposes, using the backward update with Q(S₂,ATTACK)=5.0:] Q(S₁, MOVE) = 2.25 after Episode 1 $$

(c) Episode 2 — ε-Greedy probability and DEFEND update:

$$ State: S₁, Q(S₁,MOVE)=2.25, Q(S₁,DEFEND)=0 Greedy action: MOVE (higher Q=2.25) ε-GREEDY PROBABILITIES (ε=0.2, |A|=2): P(MOVE) = (1−ε) + ε/|A| = 0.8 + 0.2/2 = 0.8 + 0.1 = 0.90 P(DEFEND) = ε/|A| = 0.2/2 = 0.10 Agent selects DEFEND (10% exploration probability). Q-LEARNING UPDATE for (S₁, DEFEND, r=1, S₁): s=S₁, a=DEFEND, r=1, s'=S₁ (self-loop, non-terminal) max_{a'} Q(S₁, a') = max(Q(S₁,MOVE)=2.25, Q(S₁,DEFEND)=0) = 2.25 TD Target = 1 + 0.9 × 2.25 = 1 + 2.025 = 3.025 TD Error = 3.025 − Q(S₁,DEFEND) = 3.025 − 0 = 3.025 Q(S₁, DEFEND) ← 0 + 0.5 × 3.025 = 1.5125 ≈ 1.51 After Episode 2: Q(S₁,DEFEND)=1.51, Q(S₁,MOVE)=2.25 Greedy action remains MOVE (2.25 > 1.51). TREND: With more DEFEND episodes, Q(S₁,DEFEND) will converge toward Q*(S₁,DEFEND)=10.0 (from Q1 — the true optimal!) $$
Mark Scheme: (a) 3 marks (formula 1, TD target 1, Q=5.0 1). (b) 3 marks (max Q(s') 1, TD target 1, Q=2.25 1). (c) 4 marks (P(MOVE)=0.90 1, P(DEFEND)=0.10 1, TD target=3.025 1, Q(S₁,DEFEND)=1.51 1).
Q3 — DQN Architecture & Experience Replay [10 Marks]
A DQN is designed for the full wargame (20×20 grid, d=410 state features, 7 actions). Architecture: FC(410→512, ReLU) → FC(512→512, ReLU) → FC(512→7, linear). Replay buffer size B=100,000. Mini-batch size b=32. Target network update every C=1,000 steps.

(a) Calculate the total number of trainable parameters in the DQN (weights + biases for all layers). [3 marks]
(b) A mini-batch contains transition (s, a=ATTACK, r=+5, s', done=False). The target network gives: Q(s', ATTACK; θ⁻)=14.2, Q(s', MOVE N; θ⁻)=11.8, Q(s', DEFEND; θ⁻)=9.4 [others ≤8]. The online network gives Q(s, ATTACK; θ)=12.1. $\gamma=0.95$. Compute the TD target y and the loss contribution from this transition. [4 marks]
(c) Explain why sampling uniformly from the replay buffer is suboptimal and describe Prioritised Experience Replay (PER) as an improvement. [3 marks]
Show Answer

(a) Total DQN parameters:

$$ Layer 1: FC(410 → 512) Weights: 410 × 512 = 209,920 Biases: 512 = 512 Subtotal: 210,432 Layer 2: FC(512 → 512) Weights: 512 × 512 = 262,144 Biases: 512 = 512 Subtotal: 262,656 Layer 3: FC(512 → 7) Weights: 512 × 7 = 3,584 Biases: 7 = 7 Subtotal: 3,591 TOTAL PARAMETERS = 210,432 + 262,656 + 3,591 = 476,679 Note: The target network θ⁻ has the same architecture → also 476,679 params Total parameters (online + target) = 953,358 ≈ ~1M parameters $$

(b) TD target y and loss computation:

$$ STANDARD DQN TD TARGET (using target network θ⁻): y = r + γ × max_{a'} Q(s', a'; θ⁻) max_{a'} Q(s',a';θ⁻) = max(14.2, 11.8, 9.4, ...) = 14.2 (ATTACK in s') y = 5 + 0.95 × 14.2 = 5 + 13.49 = 18.49 CURRENT ONLINE ESTIMATE: Q(s, ATTACK; θ) = 12.1 TD ERROR: δ = y − Q(s,a;θ) = 18.49 − 12.1 = 6.39 (positive: Q underestimates!) LOSS CONTRIBUTION from this transition: L = (y − Q(s,a;θ))² = (18.49 − 12.1)² = 6.39² = 40.83 Mean loss over batch of 32: averaged across all transitions This gradient will INCREASE Q(s, ATTACK; θ) by α×δ per update DOUBLE DQN VARIANT: Action selection: a* = argmax_{a'} Q(s',a';θ) = ATTACK (14.2-equiv in online) [assume online also gives ATTACK as best in s'] Evaluation: y_DDQN = 5 + 0.95 × Q(s', ATTACK; θ⁻) = 5 + 13.49 = 18.49 [Same here since same action selected — difference appears when online and target networks disagree on best action in s'] $$

(c) Prioritised Experience Replay (PER):

$$ PROBLEM WITH UNIFORM SAMPLING: Transitions in replay buffer have VERY different learning value. Transition with |δ|=0.01 (already well-learned) contributes almost nothing to the gradient. Transition with |δ|=6.39 (highly informative, as in our example above) drives learning. Uniform sampling wastes computation on already-learned transitions. PRIORITISED EXPERIENCE REPLAY (Schaul et al., 2015): Assign priority p_i to each transition proportional to |δ_i|: p_i = |δ_i| + ε_small (ε_small prevents zero priority) Sampling probability: P(i) = p_i^α / Σ_j p_j^α α=0: uniform α=1: full prioritisation Typical: α=0.6 (partial prioritisation) IMPORTANCE SAMPLING WEIGHTS (to correct for bias): w_i = (1 / (N × P(i)))^β (β annealed from 0.4 to 1.0) Multiply loss by w_i: reduces bias from non-uniform sampling WARGAME BENEFIT: High-|δ| transitions (surprising captures, unexpected losses) are replayed more often → faster learning of rare but critical events. Converges ~40% faster than uniform replay in practice. $$

Q4 — DQN Convergence & Operational Analysis [10 Marks]
(a) The vanilla DQN achieved 74% win rate vs random, while Dueling+Double DQN achieved 93% — an improvement of 19 percentage points. Attribute this improvement quantitatively: what fraction came from (i) Replay Buffer, (ii) Target Network, (iii) Double DQN, and (iv) Dueling DQN based on the ablation results table? [4 marks]

(b) The DQN-advisory deployment recommends the top-3 actions with Q-values at each turn. An operator reports: "In battle phase 3, the DQN consistently recommends ATTACK even when our artillery support has just been destroyed — a factor the sensor suite doesn't capture." Diagnose this failure mode in RL terms and propose TWO specific technical mitigations. [4 marks]

(c) What is catastrophic forgetting in the context of DQN training on the curriculum (5×5 → 10×10 → 20×20)? How does Experience Replay partially mitigate it, and why is it not a complete solution? [2 marks]
Show Answer

(a) Ablation attribution of 19% improvement:

$$ From results table (vs random opponent): Vanilla DQN (no replay, no target): 74% baseline DQN + Replay only: 83% +9pp → REPLAY contribution: 9pp DQN + Replay + Target: 88% +5pp → TARGET NET contribution: 5pp Double DQN (+ Replay + Target): 91% +3pp → DOUBLE DQN contribution: 3pp Dueling + Double DQN: 93% +2pp → DUELING contribution: 2pp Total improvement: 93% − 74% = 19 percentage points Breakdown: (i) Experience Replay: 9/19 = 47.4% of improvement (largest single factor) (ii) Target Network: 5/19 = 26.3% (iii) Double DQN: 3/19 = 15.8% (iv) Dueling DQN: 2/19 = 10.5% Replay is the single most important innovation (stabilising training by breaking correlation), followed by target network (fixing moving target). $$

(b) Artillery-destruction failure mode and mitigations:

$$ FAILURE MODE DIAGNOSIS: "Artillery support destroyed" is a PARTIALLY OBSERVABLE variable not captured in the state vector s. The state encoding includes unit positions, ammo, morale — but evidently not artillery AVAILABILITY or READINESS status. In RL terms: the MDP VIOLATES THE MARKOV PROPERTY for this factor. Two states (s₁: artillery intact, s₂: artillery destroyed) produce the same state vector but have radically different optimal policies. The DQN cannot distinguish them → always recommends ATTACK (learned as optimal when artillery support is the norm in training scenarios). MITIGATION 1: EXPAND THE STATE VECTOR Add artillery availability features to s: artillery_count: [0-12] artillery_ammo: [0-100%] artillery_status: [operational/degraded/destroyed] The Markov property is then satisfied for this factor. DQN will learn: when artillery_count=0 → Q(ATTACK) drops significantly. MITIGATION 2: TRAIN ON SCENARIOS WITH ARTILLERY LOSS If training scenarios never (or rarely) include artillery destruction events, the DQN never learns the appropriate conservative response. Ensure training scenarios include: - Random artillery destruction events (e.g., 20% of episodes) - Counter-battery fire scenarios - Low-support scenarios throughout curriculum The DQN will then learn robust policy across support conditions. $$

(c) Catastrophic forgetting and Experience Replay partial solution:

$$ CATASTROPHIC FORGETTING IN CURRICULUM: When transitioning from 10×10 training to 20×20, the network is fine-tuned on new 20×20 experiences. Gradient updates for 20×20 scenarios overwrite the weights encoding 10×10 tactical knowledge. The DQN "forgets" earlier learned strategies as new training dominates the weight updates. HOW REPLAY PARTIALLY MITIGATES: By keeping a MIXED replay buffer of experiences from all phases (if buffer persists across curriculum phases), mini-batches contain transitions from earlier phases. Gradients from 5×5 experiences in the batch resist overwriting earlier knowledge. The network updates to simultaneously serve experiences from all scales. WHY IT IS NOT A COMPLETE SOLUTION: ① The replay buffer has fixed size (100K) — earlier phase transitions are gradually evicted as new 20×20 experiences fill the buffer. Eventually, 5×5 experiences disappear from the buffer entirely. ② 20×20 experiences dominate later in training (recency bias in buffer content) → earlier knowledge still fades over time. Complete solutions: Elastic Weight Consolidation (EWC) — penalises changes to weights important for previous tasks — or Continual Learning architectures with task-specific parameter subsets. $$
